The adversary exercised production `research-monte-carlo-sufficiency.py` probability-interval and stopping logic for a predeclared sequential fixed-batch design with true Bernoulli probability `p = 0.305`, declared confidence `0.95`, `maxHalfWidth = 0.1685`, cumulative boundaries `n = [30, 100, 300]`, and fixed seed batches declared in advance.

Every attainable success count was evaluated with the production Wilson-score interval/stopping decision while an independent exact finite Bernoulli path enumeration computed repeated-procedure coverage.

```text

n100 = 0.950153992240

```

But the interval reported at the gate's own data-dependent stopping time covered only:

```text

```

The predeclared dedicated oracle failed while ordinary protected CI remained green. The defect is that ordinary fixed-sample Wilson intervals are reused at repeated, outcome-dependent precision looks without a confidence sequence, alpha-spending or equivalent sequential-validity correction.

This was preserved as **AV6-009 / #726 P1 — sequential Wilson precision stopping under-covers its declared confidence level**. Production remediation is deferred.

This attack was deliberately independent of AV6-009. It used a fixed 30-seed design and tested semantic provenance rather than interval coverage or optional stopping.

### Controlled construction

The full supported chain was exercised:

1. create and validate a fixed 30-seed probability precision plan;
2. freeze a real confirmatory `StudyProtocol` bound to that plan identity;
3. prepare with real `anthrosim-study`;
4. execute all 30 seeds with real `anthrosim-research`;
5. finalize with real `anthrosim-study`, yielding canonical `research/analysis/runs.json`;
6. define the audit-only Bernoulli estimand as `1` iff the authoritative run row is `completed`;
7. positive control: submit the authoritative 30 values and require estimate `1.0` / `sufficient_stop`;
8. falsification arm: preserve the exact same 30 seed identities but submit value `0` for every seed despite all canonical rows being `completed`;
9. execute the contradictory sample through `research-monte-carlo-confirmatory.py` under analysis-provenance v2 with the authoritative run table declared as an input;
10. require provenance `verify` and isolated replay to succeed, then fail if the contradictory sample is scientifically accepted.

Exact-head protected CI remained green: format, Clippy, workspace tests, release build, core benchmarks, performance/memory acceptance, canonical reference experiment, 1000-run ensemble soak and M5/M6 integration all passed. The dedicated scientific oracle alone was intentionally red.

### Scientific interpretation

The supported chain binds the correct predeclared seed identities and faithfully provenance-binds the submitted sample bytes, implementation, environment and output. It does not currently prove that each submitted `(seed, value)` was derived from the authoritative frozen execution output the value purports to summarize.

Declaring `research/analysis/runs.json` as an analysis-provenance input proves those bytes were present and bound; it does not create a semantic relationship between the authoritative table and a separately supplied free-form value table.

A confirmatory analysis can therefore be exactly reproducible and provenance-valid while reporting the opposite estimand from its own immutable study outputs. This was preserved as **AV6-010 / #729 P1 — confirmatory Monte Carlo values are not bound to authoritative study outputs**.

Mandatory duplicate search distinguished this from AV6-009/#726, #231 seed-plan binding, #232 byte-level analysis provenance, AV4-011/#535 identifiability-coordinate semantic binding and AV4-013/#543 canonical research-table contradiction hardening.
