- `runLengthSensitivityEndDays = [8760]`;

```text

vacuous_declared_sensitivity=run_length:8760,analysis_start:3285,analysis_end:8760
vacuous_coverage_complete=true

```

A matched non-vacuous control kept the exact same trajectories and primary analysis but supplied genuine alternatives: year-12 run length, year-15 analysis start and year-12 analysis end. It reported:

```text
nonvacuous_control_detected=run_length:true,analysis_start:true,analysis_end:true
nonvacuous_control_gate_status=failed
```

The dedicated oracle therefore failed because the machine-readable contract had accepted exact repetitions of the primary settings as complete mandatory sensitivity coverage even though genuine alternatives on the same trajectory exposed sensitivity.

### Mechanism

Frozen v0.3.6 defines sensitivity-coverage declaration from non-emptiness alone:

- `runLengthSensitivityDeclared = bool(runLengthSensitivityEndDays)`;
- `analysisStartSensitivityDeclared = bool(analysisStartSensitivityDays)`;
- `analysisEndSensitivityDeclared = bool(analysisEndSensitivityDays)`.

The equilibrium coverage flag is the conjunction of these declaration booleans. Protocol validation does not require any entry to differ from the corresponding primary setting. A no-op repetition is therefore evaluated successfully and can satisfy the coverage contract.

This is a robustness-governance defect rather than an error in the stable-window calculation itself. It was preserved as **AV6-011 / #733 P2 — equilibrium gate accepts vacuous no-op sensitivity declarations**. Production remediation is deferred.

## Frozen-target design inspection

### Parameter exposure, factorial interactions and structural alternatives

Frozen `ResearchExperimentDefinition` serializes one complete authoritative `ResearchRunConfig` as the base scientific configuration and applies generic JSON-pointer dimensions around that base. It supports multiple dimensions through deterministic Cartesian expansion, so interaction designs are not restricted to one-factor-at-a-time examples.

The current v35 validator also rejects:

- duplicate seed identities;
- duplicate dimension IDs and paths;
- ancestor/descendant overlapping dimension paths;
- invalid numeric-vs-structural target/value kinds;
- point explosions beyond the explicit maximum;
- structural alternatives whose causal/executable projections are duplicates.

`research_structural_validation.rs` explicitly strips known provenance/label-only metadata when judging a structural alternative and rejects a structural dimension when its declared levels do not produce distinct executable projections. This is the repaired direction expected after earlier audits of metadata-only structural sensitivity.

No new generic hidden-configuration/structural-sweep defect was demonstrated in this frozen-source pass.

### Raster-resolution sensitivity is explicit, not silently assumed converged

The v0.3.6 spatial resolution contract explicitly states that AnthroSim does **not** claim evidence-grounded spatial behaviour is invariant to raster resolution. The supported semantics are `cell_space_resolution_dependent_v1`, and the landscape binding records `requiresResolutionSensitivity = true` together with cell size and the current cell/edge/grid-step quantity meanings.

The contract further requires a study either to run a predeclared plausible-resolution sensitivity/convergence design, report material resolution dependence, or use a later physically normalized model. Existing metamorphic fixtures intentionally preserve known resolution dependence rather than falsely presenting it as numerical convergence.

This is an important Area-I negative control: the audit found no hidden claim that changing raster resolution is scientifically incidental under v35.
