### Executable mechanism

`classify_trajectory(...)` supplies a metric-derived `regimeSignature` only for stable/cyclic-stable runs. A drifting run has no regime signature.

The grouping layer then uses:

```python
def run_outcome_label(run):
    signature = run["primary"]["regimeSignature"]
    return signature if signature is not None else f"status:{run['primary']['status']}"
```

Every drifting run is therefore reduced to the same `status:drifting` token regardless of trajectory magnitude, terminal level, direction or other declared claim-relevant metric information. The initialization/environment frequency comparison operates on those lossy labels and can consequently report two materially different transient outcome families as identical.

This is a false negative in aggregate observability/path-dependence reporting; the per-run `drifting` classification itself is correct.

### Normative mismatch

`docs/research/long-run-regime-diagnostics-v1.md` states that initialization/environment dependence compares the **full normalized outcome distributions, not just which regime labels appear**. That statement is not true for non-stable outcomes under v0.3.6: those outcomes reach the dependence layer only as broad status labels.

The same contract explicitly supports `claimMode: explicitly_transient`, so drifting outcomes are not merely error cases outside the intended research surface.

The demonstrated defect was preserved as **AV6-014/#745 P2 — long-run initialization-dependence summary collapses materially distinct drifting trajectories**.

## Broader frozen-target observability review

### Undefined denominators

The v35 undefined-statistic contract distinguishes:

- numeric zero = a defined statistic whose measured value is zero;
- `null` = mathematically undefined because the observation denominator is empty;
- operational censoring = a separate lifecycle/provenance state.

Living-condition and move-conditioned migration means preserve this distinction in run manifests, metric snapshots, point analysis and Explorer presentation. No fresh empty-denominator sentinel defect was demonstrated.

### Weighting and occurrence versus conditional quality

Migration point analysis separates occurrence/frequency from conditional move-quality statistics and also distinguishes run-weighted summaries from pooled-per-move quantities where those estimands differ. No fresh run-versus-event weighting conflation was demonstrated.

### Cumulative quantities and analysis windows

Core metric snapshots contain both state quantities and cumulative since-start counters. The analysis-window contract explicitly warns that dropping pre-window snapshots does not turn cumulative counters into window totals. Derived analysis must difference snapshots or use raw events where a window-specific total is intended.

The current source review found this boundary explicit rather than silently treating cumulative counters as window totals.

Exposure-aware summaries preserve realized simulated time and explicit terminal-outcome fractions rather than silently treating all incomplete durations as equivalent.
