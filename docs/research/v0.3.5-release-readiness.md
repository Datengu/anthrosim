# AnthroSim v0.3.5 release readiness

**Preparation date:** 2026-09-07
**Preparation base:** protected `main` `4dde49b46082b359d42bf30f1ef81d6fa49f4adf`
**Candidate software version:** `0.3.5`
**Candidate model semantics:** `anthrosim-model-semantics-v33`
**Previous immutable release:** `v0.3.4` / `anthrosim-model-semantics-v25`
**Tag state in this preparation record:** intentionally not created yet

## Scope

This record prepares the already-reviewed post-Audit-v4 state for a named v0.3.5 patch release. Scientific Audit v4 is not reopened. No new simulator mechanism or causal-semantics change is introduced by the version bump.

The preparation starts only after the second post-v0.3.4 documentation-consistency audit was merged into protected `main`. That audit closed the remaining living-document/status drift found after the first synchronization pass.

## Identity decision

v0.3.5 freezes **model semantics v33**. Software/package release identity advances from 0.3.4 to 0.3.5, while `MODEL_SEMANTICS_ID` remains v33 because release naming itself does not alter authoritative scientific behaviour.

The immutable v0.3.4/v25 tag remains the Scientific Audit v4 discovery target. Audit-v4 and older release/evidence documents therefore retain v0.3.4 where it is a historical identity. Rewriting those records to v0.3.5 would destroy provenance rather than improve consistency.

## Release-preparation synchronization

The release-preparation change synchronizes:

- root workspace version and both AnthroSim workspace entries in `Cargo.lock` to `0.3.5`;
- `CITATION.cff` to `0.3.5` with the 2026-09-07 v33/Audit-v4 release description;
- living README, roadmap, architecture, research index, TRACE, ODD, ODD+D, normative scientific-model, citation and agent guidance to the v0.3.5/v33 release line;
- release/versioning policy to preserve v0.3.4/v25 while adding v0.3.5/v33;
- permanent documentation-consistency checks to recognize v0.3.5/v33;
- a dedicated `docs/releases/v0.3.5.md` release record.

Reviewed experiment/reference records keep their actual execution provenance. In particular, an archived v33 run generated while the package version was 0.3.4 remains labelled 0.3.4; the v0.3.5 package bump does not fabricate a rerun.

## Completion gate before tagging

This preparation is ready to freeze only after its release PR is merged and the resulting exact protected-main SHA has all ordinary required contexts plus the release-specific M8.6, M9.7 and RustSec checks green. The fail-closed release-tag verifier must also confirm that Cargo workspace identity, lockfile workspace identities, citation version and release-note tag all match `v0.3.5`.

The tag is intentionally outside this preparation record. Once those exact-SHA conditions are satisfied, `v0.3.5` can be preserved in a separate explicit tagging step without modifying the candidate source tree.
