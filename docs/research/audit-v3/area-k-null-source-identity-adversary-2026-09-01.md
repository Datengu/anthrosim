# Audit v3 Area K adversary — null source identity collision

Immutable discovery target: `v0.3.3` / `d3b6fc0b0750933b57252c9087513d156d88f218` / `anthrosim-model-semantics-v21`.

This is discovery evidence only. It does not repair the demonstrated defect.

## Question

Can two source-distinct executables be represented as the same immutable versioned research execution and can a retry retain child bundles produced by the other executable?

## Frozen source construction

`SourceRevisionIdentity::current()` contains only:

- package `modelVersion`;
- `modelSemanticsId`;
- optional `gitCommit` from the compile-time `ANTHROSIM_GIT_COMMIT` environment value.

The shared build helper deliberately leaves `ANTHROSIM_GIT_COMMIT` unset when Git metadata cannot be resolved, so runtime provenance records `gitCommit: null`.

`anthrosim-research::build_manifest()` accepts this identity without requiring `gitCommit`, incorporates it into `researchId` and each `runId`, and publishes it as the immutable research source identity.

On `--retry`, the runner rebuilds the expected manifest from the current executable. Immutable metadata is accepted when it equals that expected manifest. Existing completed child bundles are retained when their manifest/checkpoint source fields equal the expected `SourceRevisionIdentity` and their experiment configuration matches the plan.

## Hand-computable two-build adversary

Construct source-distinct builds A and B with:

- package version `0.3.3`;
- model semantics `anthrosim-model-semantics-v21`;
- no usable Git metadata at build time;
- no explicit `ANTHROSIM_GIT_COMMIT` override;
- at least one tracked/source difference between A and B that does not change the package version or semantics string.

Both executables obtain exactly:

```json
{
  "modelVersion": "0.3.3",
  "modelSemanticsId": "anthrosim-model-semantics-v21",
  "gitCommit": null
}
```

For an identical research definition D:

- `definitionIdentity_A == definitionIdentity_B` because D is identical;
- `source_A == source_B` because both contain the same version/semantics/null tuple;
- therefore `researchId_A == researchId_B`;
- every seed-specific `runId_A == runId_B`.

Let A execute D to completion. Then invoke B on the same root with `--retry` and D.

The retry expected manifest reconstructed by B is byte/structure-equal to A's immutable manifest because the only source discriminator is the colliding null identity. For each completed child bundle, `validate_completed_run()` computes no source mismatch because all compared source fields are equal, including `None == None` for `gitCommit`. The bundle is therefore retained instead of reexecuted.

Thus the research root can now be accepted by executable B as its own exact immutable research execution even though the child result was generated by source-distinct executable A.

## Quantitative identity cardinality

For any number N >= 2 of source-distinct builds sharing the same package version and model-semantics string while lacking Git identity, the source-identity mapping has cardinality:

- distinct source trees: N
- represented source identities: 1

The collision rate is therefore `(N - 1) / N`; for the minimal two-build adversary, two distinct sources collapse to one represented identity.

## Scientific consequence

The versioned exact-configuration research runner can misidentify the executable source that generated an accepted completed run and can preserve that result across a retry from a different executable. If the source difference affects scientific execution while version/semantics labels were accidentally or maliciously unchanged, the immutable metadata positively claims sameness where source execution is different.

This matches the scientific-audit P0 class: provenance can misidentify the executed scientific configuration/source and continuation/retry can accept it as authoritative.

## Scope

This finding is distinct from historical #94. The repaired versioned-sweep adapter fails before/after execution when exact source provenance is unavailable; this adversary concerns the generic `anthrosim-research` runner itself accepting a null source identity as an immutable research/run identity.

The explicit build-time override is not independently attacked here. The demonstrated smallest causal defect is that a workflow described as exact/versioned research accepts a non-unique missing source identity as sufficient identity.
