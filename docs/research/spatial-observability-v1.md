# M8.5 spatial observability v1

## Purpose

M8.5 makes landscape-bound AnthroSim runs measurable and inspectable without making visualization authoritative.

The authoritative simulation remains the M1-M4/M8.4 execution state, event stream and checkpoint. M8.5 is a downstream analysis layer that can be regenerated from preserved run artifacts. Removing the explorer or every M8.5 artifact must leave simulation execution, RNG streams, checkpoint compatibility and model semantics unchanged.

The public contract is deliberately case-study-neutral. It supports controlled evidence-grounded spatial experiments without embedding a known site, route, historical destination or desired archaeological outcome.

## Artifact and provenance classes

M8.5 keeps four classes visibly separate:

1. **Normalized input** — `landscape.json`, including declared CRS/grid geometry, source-layer values, units, domains, nodata and evidence-input references. These are model inputs, not simulated observations or historical truth.
2. **Authoritative model-facing state** — `world.json` and terminal checkpoint state. In transformed runs, selected world fields may be M8.4 transformations of normalized inputs; other fields may retain synthetic/default semantics.
3. **Derived observability** — `spatial-observability.json`, deterministically calculated from preserved authoritative artifacts. These values do not feed back into execution.
4. **Reconstructed display** — historical explorer views reconstructed from founder state plus authoritative events. These are convenient views and are not additional authoritative history.

A realistic map is not a validation result.

## Downstream postprocessor

Spatial observability is generated by a separate binary:

```text
anthrosim-spatial-observability run --run-dir RUN
anthrosim-spatial-observability run --run-dir RUN --check
anthrosim-spatial-observability tree --root EXPERIMENT_OR_SWEEP
anthrosim-spatial-observability tree --root EXPERIMENT_OR_SWEEP --check
```

`run` derives one report. `tree` discovers landscape-bound run bundles beneath an M7 experiment or sweep and processes them in stable path order.

`--check` does not write. It deterministically regenerates the report in memory and requires exact equality with the existing `spatial-observability.json`.

The postprocessor requires the preserved normalized landscape, authoritative transformed/baseline world, a resolvable original founder population and checkpoint. For an inert M8.3 landscape-bound run, the `LandscapeCheckpoint` wrapper must reconcile with `checkpoint.json` and the exact landscape binding. For a transformed M8.4 run, the `SpatialLandscapeCheckpoint` wrapper must additionally reconcile the spatial mechanism binding and transformed world identity.

### Resume population semantics

`initial-population.json` and `resume-start-population.json` describe different moments and must never be treated as aliases:

- `initial-population.json` is the original day-zero founder population used as the baseline for full-history event replay;
- `resume-start-population.json` is the authoritative population at the checkpoint boundary from which a resumed execution continued.

A new-directory resume may legitimately contain only `resume-start-population.json`. The checkpoint still preserves the immutable experiment seed and population initialization configuration, while `world.json` preserves the exact authoritative world used by the resumed run. Under the same compatible model semantics, M8.5 deterministically regenerates the original founders from those inputs and uses that regenerated population as day zero.

The resume-boundary population is validated as a population artifact but is **never** substituted for founders. Doing so would replay pre-resume births, deaths and migrations on top of an already-evolved population and corrupt full-history occupancy/person-day accounting.

This rule applies consistently to `anthrosim-spatial-observability run`, `tree`, and completed-run semantic bundle validation. If neither an original founder snapshot nor the population provenance required for the supported resumed-bundle contract is present, processing fails rather than inventing a baseline.

## Report identity

Every report records the source run and environment identities needed to prevent accidental cross-run aggregation:

- model version;
- core model-semantics identity;
- optional git commit;
- seed;
- terminal simulation day;
- terminal run-state digest;
- landscape identity and digest;
- authoritative world digest;
- optional M8.4 spatial-model-semantics identity;
- optional spatial transformation-config identity.

These source fields apply to every derived row in the report. M8.6 aggregation must preserve the contributing run identities rather than treating a spatial summary as an anonymous observation.

## Per-cell reconstruction

M8.5 does not add an authoritative historical state archive. Instead, occupancy statistics are derived from data that already exist:

1. resolve the original day-zero founders from `initial-population.json`, or deterministically reconstruct them for a supported resumed bundle;
2. initialize living counts from that founder population;
3. replay authoritative events in sequence order;
4. births add one living person to their recorded cell;
5. deaths remove one living person from their recorded cell;
6. household migrations move the event's exact `peopleMoved` count from origin to destination;
7. finalize each cell at the terminal checkpoint day;
8. independently count living people by cell from the terminal checkpoint population;
9. require exact cell-by-cell agreement between event reconstruction and terminal authoritative state.

A disagreement is an error, not a visualization warning.

### Interval semantics

For a cell whose current living population is `N`, an event at day `D` closes the interval from that cell's previous change day up to `D` using the pre-event state. The event then changes state for the interval beginning at `D`.

Consequences:

- events on the same simulation day contribute zero elapsed time between one another;
- event sequence still determines the exact reconstructed state after those zero-duration transitions;
- an occupied interval `[A, B)` contributes `B - A` occupied days;
- the same interval contributes `N * (B - A)` living person-days;
- the terminal interval is closed at the checkpoint day.

This convention is deterministic and does not invent within-day timing that the authoritative event model does not record.

## Per-cell derived observables

For each cell, v1 records:

- initial living population;
- terminal living population;
- occupied duration in simulation days;
- occupancy persistence in permille when run duration is non-zero;
- living person-days;
- births;
- deaths;
- resource-scarcity deaths;
- household-migration moves in and out;
- people moved in and out.

The same row also exposes selected authoritative model-facing/checkpoint values beside the derived values:

- movement cost;
- water accessibility;
- base productivity;
- initial food stock;
- terminal food stock.

This adjacency is for traceability. It does not change their provenance class.

## Spatial concentration and persistence summaries

### Cell-time occupied

```text
occupied_cell_days = sum(cell occupied duration days)
cell_time_occupied_permille =
    floor(1000 * occupied_cell_days / (run_duration_days * grid_cell_count))
```

It measures how much of the available cell-time was occupied by at least one living simulated person. A zero-duration run reports no fraction rather than inventing one.

### Largest-cell terminal share

```text
largest_cell_share_permille =
    floor(1000 * max_terminal_cell_population / terminal_population)
```

It is absent if terminal population is zero.

### Terminal population Herfindahl concentration

```text
HHI_per_million =
    floor(1,000,000 * sum(n_i^2) / N^2)
```

where `n_i` is terminal living population in cell `i` and `N` is terminal living population. It is absent when `N = 0`.

This is a concentration statistic, not a settlement classifier. M8.5 does not decide that a particular HHI value constitutes a village, centre or hierarchy.

## Migration observables

Authoritative household-migration events are aggregated into deterministic origin/destination flows keyed by exact cell IDs.

Each flow records:

- origin;
- destination;
- recorded Manhattan distance in cells;
- number of household moves;
- total people moved.

A second table groups moves and people by recorded distance. Aggregate move, people and total-distance counts must reconcile with the terminal migration checkpoint state.

These are simulated flows. They are not inferred historical routes and do not imply that straight lines between cell centres represent travelled paths.

## Resource observability boundary

M8.5 exposes terminal per-cell food stock because that state exists in the checkpoint, and it aggregates authoritative resource-scarcity deaths by event cell.

The current model does **not** serialize enough information to recover:

- historical per-cell food stock between serialized checkpoint boundaries;
- per-cell unmet resource need;
- continuous historical person condition between authoritative death/checkpoint observations.

These are listed explicitly in `unavailableObservables`.

M8.5 must not interpolate, back-calculate or visually smooth those missing histories. A later research question can justify new authoritative/derived instrumentation, but absence is preferable to fabricated precision.

## Normalized layer catalogue

The report preserves one descriptor for every normalized landscape layer:

- exact layer ID;
- role;
- unit;
- declared value domain;
- optional evidence-input ID;
- nodata-cell count;
- source artifact.

The explorer renders original values directly from `landscape.json`. `null` remains nodata and is displayed distinctly rather than coerced to zero or filled from neighbours.

## Explorer

Landscape-bound runs gain an additive read-only M8.5 panel. Synthetic M6 runs continue to work without any spatial files.

The spatial panel exposes:

- CRS/spatial-reference text;
- coordinate unit, origin, cell size and grid dimensions;
- landscape/run/spatial identities when available;
- normalized layer catalogue and evidence-input references;
- normalized input overlays with nodata preserved;
- derived occupancy persistence, person-days, terminal distribution, scarcity deaths and migration-out overlays when a report exists;
- per-cell source values, authoritative model-facing values and derived observables in separate sections.

The existing historical population map remains a reconstructed display. The M8.5 panel does not convert it into authoritative historical state.

## Validation boundary

M8.5 can establish that:

- spatial summaries are deterministic functions of preserved artifacts;
- event-derived terminal distribution reconciles with authoritative checkpoint state;
- aggregate births, deaths, scarcity deaths and migration totals reconcile with existing summaries;
- source run/environment identities are attached to the report;
- normalized nodata is preserved;
- the explorer is read-only and optional;
- removing M8.5 leaves authoritative execution unchanged.

It cannot establish that:

- the normalized environmental reconstruction is correct;
- an M8.4 transformation is empirically justified;
- simulated occupation resembles or explains a particular archaeological record;
- concentration implies a specific social or settlement category;
- visually plausible spatial structure is evidence of historical accuracy.

Those questions require the predeclared M8.6 benchmark, sensitivity analysis, relevant external evidence and later domain review.
