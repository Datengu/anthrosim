## Fresh pass 1 — small-n sequential mean coverage

Evidence PR #639, exact head `97fa8ee6636b89a7bdb3660583a2484216a9ef5f`.

Dedicated workflow:

- run `34179975096`
- job `101916912997`

The supported precision plan used:

- estimand `mean`;
- confidence `0.95`;
- `maxHalfWidth=0.1`;
- sequential first batch `[1,2]` with a later batch already predeclared;
- first values `[0,0]`;
- executable method `normal_clt_mean_se`.

Independent exact reference process:

```text
X = 0  with probability 0.9
X = 10 with probability 0.1
E[X] = 1
```

Both first draws are zero with probability `0.81`. On that event the gate emitted:

```text
decision=sufficient_stop
n=2
estimate=0.0
interval=[0.0,0.0]
half_width=0.0
false_stop_probability=0.810000
max_overall_coverage=0.190000
nominal_confidence=0.950000
```

The scientific oracle failed exactly because the machine-readable nominal 95% interval can miss the true mean on an event of probability 0.81, bounding overall coverage of the stopped procedure above by only 0.19 even if all other paths covered.

**Finding: AV5-005 / #640 / P1.** The mean/continuous normal-CLT gate has no executable minimum-sample or finite-sample-validity guard, so a confirmatory sequential analysis can terminate with severely unsupported nominal confidence. A prose warning that very small samples may require another method does not prevent `sufficient_stop`.

This is distinct from #334 (quantile rank coverage), #410 (two-arm covariance), #528 (numeric fidelity) and #214 (paired-seed interpretation).
