## Adversarial test: stochastic uncertainty is invisible to the identification decision

The analyzer validates each `point.outputs[observable]` as exactly one finite scalar and `_accepts(...)` applies the deterministic rule

`abs(observed - target) <= tolerance`.

There is no input field or upstream binding for replicate count, seed identity, Monte Carlo SE/CI, or a #231 replicate-sufficiency result.

A minimal supported construction therefore produces a false-positive identification claim:

- target = 0;
- calibration tolerance = 0.05;
- point A: `x=0`, reported stochastic mean = 0.00;
- point B: `x=1`, reported stochastic mean = 0.10;
- claimed parameter = `x`;
- maximum normalized acceptable width = 0.25.

The current exact-scalar rule accepts A, rejects B, leaves a single acceptable `x`, and therefore returns `researchGate.passes=true`.

Now attach the scientifically relevant fact that each point mean came from only four stochastic replicates with Monte Carlo SE = 0.20. The apparent A/B separation is only 0.5 SE. The analyzer's result cannot change because the schema cannot represent that uncertainty. Holding the exact same point estimates fixed while changing Monte Carlo SE from 0.001 to 1.0 likewise leaves the result bit-for-bit unchanged even though the evidence for discrimination changes by three orders of magnitude.

This is a scientific invariance failure: stochastic precision is relevant to whether parameter points are distinguishable, yet the identification gate is invariant to it.

## Finding

**AV2-011 — P1 — stochastic calibration summaries are treated as exact values by the identifiability gate.**

Issue: #338.

Scientific consequence: a supported stochastic calibration can receive `declared_claim_identified` because finite-seed noise happens to place one point inside a hard tolerance and alternatives outside it. The machine gate can therefore overstate parameter or mechanism identification even when simulation Monte Carlo uncertainty is larger than the tolerance or inter-point separation.

This is distinct from #217's original missing-governance finding: the v1 finite-design logic exists and works for exact/deterministic inputs. It is also distinct from #231/#334: those concern precision estimation/sufficiency itself; #338 concerns the missing coupling between stochastic precision evidence and calibration/identification decisions.

## Anti-bias / limits

No claim is made that a single universal uncertainty-aware acceptance rule is appropriate for all estimands. The required contract is fail-closed linkage between stochastic calibration summaries and precision adequate for the declared discrimination task.

The existing synthetic ratio/sum benchmark remains useful positive evidence for exact structural/practical equifinality. It does not exercise stochastic outputs, so it cannot falsify #338.
