## Long-run/population-structure evidence reviewed

The prior #239 / PR #303 model-analysis work supplies explicit synthetic declining/replacement/growing controls rather than treating the historical synthetic schedule as neutral. Its analytical female age/birth-spacing model reports approximately:

- negative control: `lambda ~= 0.99504/year`, lifetime daughters ~= `0.86245`;
- replacement control: `lambda ~= 1.00002/year`, lifetime daughters ~= `1.00074`;
- positive control: `lambda ~= 1.00417/year`, lifetime daughters ~= `1.13076`.

Those controls were also executable-tested over fixed multi-seed late-growth windows.

The later #304 / PR #307/#308 demographic-baseline study provided a larger structural counterfactual: a 288-run exploratory factorial and an independent 384-run confirmation. The preserved result shows that an intrinsically positive schedule can be approximately stationary with fixed founder households (`-0.002%/yr`, 95% Monte Carlo CI `-0.062%` to `+0.058%`) yet decline strongly under deterministic household fission (`-0.994%/yr`, `-1.198%` to `-0.789%`), with mate limitation increasing from 11.3% to 38.7%. This supports the current policy that there is no universal neutral demographic baseline and that demography/household structure must be declared explicitly.

Area B therefore did not reopen the historical negative-growth finding; the current repository already treats background demographic direction as an explicit experimental/structural condition.

## Adversarial founder reproductive-chronology test

### Source boundary

`FounderPopulationDefinition::validate_parent(...)` requires that a declared parent:

1. exists;
2. has the expected reproductive sex; and
3. has `birth_day < child.birth_day`.

It does not require a biologically possible parent age at the child's birth. The analogous declared pre-run `lastBirthDay` check requires only that the event be after the founder's own birth and before day zero, so the same underlying ordering-without-plausibility weakness applies to reproductive prehistory.

### Executable counterexample

Temporary draft audit PR #319 constructed:

- female parent ID 1: `birth_day = -101`;
- child ID 2: `birth_day = -100`;
- child `female_parent = ID 1`;
- otherwise valid one-cell declared founder state.

The parent is one day old at the child's birth. On the protected-main test merge, the adversarial test reported:

```text
test audit_probe_declared_founder_accepts_one_day_parent_child_age_gap ... ok
```

That means `Simulation::new(...)` accepted the impossible founder genealogy exactly as hypothesized.

### Finding

**AV2-003 — P2 — declared founder reproductive chronology validates ordering but not biological possibility.**

Issue #320 records the demonstrated defect. The issue also includes the same underlying `lastBirthDay` plausibility gap so one scientific defect remains one ticket.

Scientific consequence is bounded but real: declared founder genealogy/history is authoritative research-facing state and can immediately affect kin-mediated M4 behaviour, genealogy/household observability, provenance interpretation and descendants. Valid generated trajectories are not corrupted; malformed research initialization fails insufficiently closed.

## PersonId relabelling metamorphic experiment

Area A left an explicit hypothesis that sequential named RNG streams might make identity/order assignments scientifically visible. Area B tested that rather than inferring from source alone.

### Design

Temporary audit harness: closed-unmerged draft PR #319.  
Final harness head: `2b54fa6dd94be51a01dc7c6d1eb2425d1444712e`.  
CI run: `33234553746`.  
Seeds: integers `1..=2000`.  
Horizon: 1 model year.  
World: one cell.  
M3 periods/year: 1.  
Resource demand and condition mortality: zero.  
Fertility: zero.  
M4: disabled.

Each arm had the same two founder states except for a consistent PersonId reassignment:

- young female: age 20, annual background mortality 0.2;
- old female: age 40, annual background mortality 0.8;
- arm A: young=ID1, old=ID2;
- arm B: old=ID1, young=ID2.

The founder label and every non-ID scientific field were kept equal. The estimator was the paired indicator that terminal living-population count differed.

### Exact expectation under sequential stream assignment

Let the first two mortality-stream uniforms be `u1,u2`. The two arms assign the 0.2 and 0.8 thresholds to opposite stream positions. Terminal count differs exactly when one, but not both, uniforms lies in `[0.2,0.8)`. Thus:

`P(count differs) = 2 * 0.6 * 0.4 = 0.48`.

The paired terminal-population difference itself has expectation zero by exchange symmetry; this test diagnoses coupling/identity assignment, not marginal demographic bias.

### Result

CI deliberately asserted zero differences so the audit log would preserve the exact count. It failed with:

```text
AUDIT DEMONSTRATION: pure PersonId relabelling changed final living population; first=Some((2, 1, 0))
left: 976
right: 0
```

Therefore **976/2000 = 48.8%** of paired seeds changed terminal survivor count solely under the PersonId swap. First mismatch: seed 2, one survivor versus zero. Under a binomial reference with `p=0.48`, `n=2000`, Monte Carlo SE is about 1.12 percentage points; the observed 48.8% is only about 0.7 SE above the exact 48% expectation.

### Disposition

This is not opened as a new Area B defect. It is stronger quantitative evidence for the already-declared #214 / PR #302 sequential-stream coupling contract: same-seed runs do not provide agent/event-level common random numbers, and bookkeeping identities determine assignment of stream positions. The controlled construction does not show marginal ensemble bias, because the two labelled systems have the same stochastic law and zero expected paired population difference.

The evidence was added to #214. Area H must revisit whether order/identity coupling causes bias or invalid uncertainty estimates in more complex state-dependent settings; Area B does not duplicate that RNG/Monte Carlo finding.
