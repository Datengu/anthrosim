## Adversarial finding: recorded analysis arguments are not execution-bound

The normative #232 contract says an analysis definition declares both exact command argv and machine-readable analysis arguments/configuration. In `scripts/research-analysis-provenance.py`, both are validated and included in the definition/provenance identity.

However scripted execution calls only:

```python
subprocess.run(definition["command"], cwd=cwd, check=False)
```

The separate `definition["arguments"]` object is not supplied to the command and is not reconciled against the actual argv/configuration consumed by the analysis.

The existing regression suite contains a direct adversarial demonstration. Its fixture command includes `--scale 2`, while `test_definition_change_changes_identity()` changes only `arguments.scale` from 2 to 3. Execution still runs `--scale 2`, produces the scale-2 result (`scaledTotal = 10`), succeeds, and publishes a new provenance identity solely because the unused arguments metadata changed.

Therefore the canonical record can simultaneously preserve:

- machine-readable analysis configuration `scale = 3`;
- actual executed argv `--scale 2`;
- output produced by scale 2;
- `executionStatus = executed_by_wrapper`;
- an exact replay that succeeds, because replay again follows the command argv rather than the declared arguments object.

Changing the unused declared scale to 3, 30 or 3000 changes provenance identity but not execution or replay output.

## Finding

**AV2-012 — P1 — downstream analysis configuration/arguments are not causally bound to executed analysis.**

Issue: #340.

Scientific consequence: a canonical confirmatory result can be cryptographically reproducible while its machine-readable filtering threshold, estimator setting, analysis window, model-comparison option or other declared analysis argument differs from what actually produced the reported number. Exact argv remains visible, so the execution is not unrecoverable, but the provenance layer can materially misattribute the scientific configuration while all verification/replay checks pass.

Independent post-repair reverification is required.

## Secondary hypothesis not promoted to a finding

The legacy `scripts/run-versioned-sweep.py` copies `source-definition.json` only after the underlying sweep returns successfully. There is therefore a narrow interruption window in which a completed sweep can exist before the wrapper source-definition copy/reproduction record is published. A later `--retry` with an executable-equivalent but differently labelled source definition deserves hardening review. This was not promoted to a separate audit-v2 issue in this pass because current research-mode #205/#230 machinery provides a stronger path and the demonstrated #340 defect is more direct and scientifically consequential.
