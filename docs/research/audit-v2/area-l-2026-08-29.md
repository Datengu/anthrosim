## Adversarial weighting test

The migration-quality point summaries are computed differently from the nearby explicitly pooled migration-distance-per-move statistic.

For each scientifically eligible run with at least one migration, the run manifest contributes one within-run mean resource/water score. `build_point_rows(...)` then calculates the point field with `mean_u64(...)` over those run-level means. Every contributing run therefore has equal weight, independent of its number of completed moves.

This is a coherent **run-weighted mean of run-level move means**, but the exported field names such as `meanMigrationDestinationResourceScorePermilleMoveObservedOnly` do not state the weighting unit, and the normative experiment documentation does not define it.

A controlled two-point construction demonstrates that the weighting choice can reverse a comparison.

### Point A

- run A1: 1 move, run mean destination score = 0;
- run A2: 99 moves, run mean destination score = 1000.

Current run-weighted point value:

`(0 + 1000) / 2 = 500`.

Mean across the 100 observed moves:

`(1×0 + 99×1000) / 100 = 990`.

### Point B

- same move counts: 1 and 99;
- both run means = 600.

Both run-weighted and move-weighted values are 600.

Thus:

- current run-weighted field ranks **B > A** (`600 > 500`);
- a pooled per-observed-move estimand ranks **A > B** (`990 > 600`).

The discrepancy is 490 permille for point A and is large enough to reverse a treatment ranking. It is not a rounding edge case.

## Finding

**AV2-013 — P2 — migration-quality point summaries do not make run weighting versus move weighting explicit.**

Issue: #342.

Neither weighting scheme is universally preferable; they answer different scientific questions. The defect is an exported research-analysis schema whose name can plausibly be read as a mean over observed moves while it actually equally weights move-observing runs. This is especially ambiguous because the adjacent `pooledMeanMigrationDistanceCellsPerMoveScientificallyEligibleOnly` explicitly labels its event-weighted estimand.

Required direction is to state the weighting unit machine-readably and, if both estimands are useful, expose them separately rather than silently replacing one with the other.

## Anti-bias / limitations

The audit does not claim that point-level run weighting is mathematically wrong. Equal weighting of stochastic runs is often the appropriate unit when the target is an expectation over replicate-level summaries. Event weighting instead answers an event-population question and can itself overweight high-activity realizations. The scientific requirement is explicit estimand definition.

The current built-in sweep summaries remain deliberately descriptive rather than inferential. Area H/J findings govern precision and inferential use beyond those descriptive values.
