# AnthroSim v0.1 specification

**Status:** implementation baseline  
**Prepared:** August 2026

> **Core rule:** Model causes, not historical outcomes. If a pattern appears, it should be explainable from simulated conditions and agent behaviour rather than from a scripted civilisation rule.

## Purpose

v0.1 proves that AnthroSim can sustain a deterministic, inspectable, performant population simulation before attempting culture, language, institutions, states, religion, trade, or complex ecology.

The first success criterion is not visual polish. It is whether a small hunter-gatherer population can show understandable growth, decline, fragmentation, and migration as consequences of explicit environmental and demographic mechanisms.

## Scope

### Must support

- versioned deterministic experiment configuration;
- synthetic spatial world generation;
- 10,000 persistent living individuals as the baseline functional target;
- stable person IDs and parent links;
- households as the minimum co-resident resource-sharing unit;
- birth, ageing, health, and death;
- renewable local food and environmental stress;
- bounded local migration decisions with inspectable factors;
- spatial indexing with no routine global all-to-all searches;
- structured events and aggregate metrics;
- run manifests tying outputs to code/configuration/seed;
- invariant validation;
- a headless runner;
- benchmark baselines.

### Should support before v0.1 is declared complete

- resumable checkpoints;
- unattended multi-seed batch runs;
- minimal local explorer for map/timeline/event/entity inspection.

### Explicitly out of scope

- real Earth, palaeoclimate, or archaeological datasets;
- cultural traits and language;
- formal settlements, trade, inequality, property, politics, religion, or warfare;
- LLM-controlled agents or generated dialogue/history;
- metre-scale pathfinding or continuous animation;
- detailed multispecies ecology;
- online multiplayer/public hosting;
- any claim that v0.1 accurately reconstructs real prehistory.

## Logical architecture

```text
Experiment definition
        ↓
Simulation host
        ↓
Environment / demography / households / survival / migration
        ↓
Authoritative packed world state + event queues + spatial indices
        ↓
Observation pipeline (events, metrics, checkpoints, manifest)
        ↓
Versioned files
        ↓
Explorer / analysis / batch comparison
```

The simulation core has no dependency on rendering, a database service, AI services, or network access.

## Core entities

### Person hot state

Initially expected fields:

- `PersonId`;
- birth time (age is derived where feasible);
- sex used by the v0.1 reproduction model;
- `CellId`;
- `HouseholdId`;
- mother/father IDs where known;
- compact health/condition state;
- short-term resource/energy pressure;
- activity/next-decision scheduling state.

Hot state should favour contiguous storage and compact IDs over allocation-heavy object graphs.

### Household

A household models co-residence, resource sharing, reproduction context, and optionally coordinated migration. It does **not** imply tribe, clan, ethnicity, or village.

### World cell

A cell contains movement cost/terrain, water accessibility, baseline productivity, renewable food stock, seasonal multiplier, temporary stress, occupancy/density, and neighbour/candidate-movement references.

## Time and scheduling

Use integer simulation time and a hybrid discrete-event / fixed-interval design.

Initial cadence guidance:

| Process | Initial cadence |
|---|---|
| environmental / food regeneration | daily or weekly |
| food consumption / health | daily |
| migration decisions | event-triggered plus periodic reevaluation |
| births | scheduled events |
| deaths | scheduled baseline risk plus health-triggered checks |
| metrics | monthly / annual |
| checkpoints | configurable, initially every 10–100 years |

The engine should evaluate a person/household only when something relevant can change.

## Behaviour

### Food and survival

Households gather from local renewable food, consume/share resources, and experience deteriorating condition under sustained scarcity. Scarcity must directionally increase mortality pressure and/or migration incentive.

### Demography

The first fertility/mortality models are transparent placeholders. Their parameters and units must be explicit and replaceable. Population accounting must always reconcile with initialized population + births - deaths.

### Migration

Migration is the main behavioural experiment in v0.1. Agents compare staying with a bounded, knowledge-limited set of alternatives. A conceptual utility is:

```text
expected resources + water/security + kin proximity
- travel cost - uncertainty - relocation risk
```

No route or destination is selected because it was important in real history.

## Observation and explanation

Minimum event types eventually include births, deaths, household changes, migration start/completion, environmental shocks, and invariant/model warnings.

Minimum aggregate metrics include total/regional population, birth/death rates, age structure, household size, health/resource stress, migration counts/distances, occupied area, and a population-fragmentation proxy.

Decision systems should be able to retain compact factor data so a researcher can inspect why a migration or survival decision was produced.

## Determinism and provenance

- every run has an explicit master seed;
- random streams are named and derived deterministically;
- system ordering is stable;
- persisted schemas are versioned;
- each run emits a manifest with software/model version, config, seed, start/end state, stop reason, and runtime statistics;
- checkpoints must resume to the same supported deterministic result as uninterrupted execution;
- parallelism cannot silently weaken determinism.

## Performance

Baseline: simulate at least 10,000 individuals for thousands of years on a normal desktop. Higher populations are benchmark targets, not excuses to simplify v0.1 correctness.

Measure:

- simulation-years per second;
- events per second;
- memory per living person and world cell;
- avoidable allocations;
- snapshot size/read-write throughput.

No routine O(N²) person-to-person search is acceptable. A database must not sit in the hot loop. Rendering must not affect headless throughput.

## Milestones

1. **M0 Skeleton:** repository, deterministic time/RNG, run config/manifest, CLI, tests, benchmark harness.
2. **M1 World:** synthetic heterogeneous world, seasons/resources, neighbours, basic map dump.
3. **M2 People:** packed person state, households, initialization, demography, genealogy.
4. **M3 Survival:** renewable food, gathering/sharing, health/starvation response.
5. **M4 Migration:** local candidate discovery, interpretable utility, household movement.
6. **M5 Observation:** metrics, events, checkpoints, causal/decision traces.
7. **M6 Explorer:** local map/timeline/entity/event inspection.
8. **M7 Batch/hardening:** ensembles, invariants, soak tests, profiling and acceptance scenarios.

## v0.1 completion statement

Version 0.1 is complete when AnthroSim is a **fast, deterministic, inspectable hunter-gatherer population simulator**. It is not complete merely because it can display civilisation-like output.
