# AnthroSim v0.3.3

`v0.3.3` is the named post-scientific-audit-v2 hardening and convergence baseline for the completed M9 capability line.

It preserves the current authoritative scientific identity:

- software version: `0.3.3`;
- `MODEL_SEMANTICS_ID = "anthrosim-model-semantics-v21"`;
- completed M9 temporary-mobility / controlled-aggregation capability;
- the repaired and reverified scientific-audit-v2 state;
- the existing M8.6 and M9.7 capability/regression references under their declared assumptions.

This release does **not** claim that AnthroSim is an empirically validated model of human prehistory, does not validate a particular archaeological reconstruction, and does not establish that no scientific defect remains.

## Why this patch release exists

The immutable `v0.3.2` release remains a documentation-convergence maintenance baseline with model semantics v19. Scientific audit v2 then independently audited the integrated framework across Areas A–N and demonstrated 15 AV2 findings. Repairs on the living line intentionally advanced authoritative semantics where required rather than rewriting the historical release:

- #326 / PR #347 corrected partial-supply temporal rounding and advanced model semantics v19 -> v20;
- #324 / PR #358 corrected household-assignment/fission semantics and advanced model semantics v20 -> v21;
- the remaining audit-v2 findings strengthened demographic chronology, competing contracts, stochastic precision, structural sensitivity, identifiability, experiment/analysis binding, migration-quality estimands, checkpoint/resume consistency and current-facing scientific documentation without hiding incompatible meaning behind the old release identity.

The final audit-v2 closure records:

- Areas A–N complete;
- all 15 AV2 findings repaired;
- all blocking P1 findings independently reverified where required by the audit protocol;
- no open P0, P1, P2 or P3 scientific finding at closure;
- current executable model semantics v21;
- no empirical archaeological claim validated merely by passing the framework audit.

See `docs/research/audit-v2/STATUS.md` for the repository-authoritative audit record.

Executable, scientific-machinery, workflow, mixed or unknown changes continue to fail closed to the full suite.

This CI optimization is process infrastructure, not an additional scientific finding or a change to model semantics.

## Historical identity remains immutable

`v0.3.3` does not retroactively redefine earlier releases:

- `v0.3.0` remains the preserved M9 capability release;
- `v0.3.1` remains the first post-M9 scientific-hardening patch;
- `v0.3.2` remains the immutable documentation-convergence release with model semantics v19;
- `v0.3.3` preserves the later repaired model semantics v21 state.

## Release verification boundary

Before the immutable-intent `v0.3.3` tag is created, the exact release commit must be the current protected `main` HEAD and must have:

- all currently required protected-main contexts successful;
- `Execute predeclared terrain null-model benchmark` successful on the exact SHA;
- `Execute predeclared M9.7 aggregation benchmark` successful on the exact SHA;
- `RustSec dependency audit` successful on the exact SHA;
- matching workspace, lockfile, citation and release-note version identity.

The repository's `Preserve named release tag` workflow performs the final fail-closed release-candidate verification before creating the tag.

## What comes next

`v0.3.3` is intended to be the fixed target for another genuinely fresh independent/adversarial scientific audit. Repeated audits are evidence of process/scientific convergence, not proof of correctness.

Only if that next audit remains clean of new blocking scientific defects should the project proceed to question-led model interrogation and a first explicitly scoped empirical case-study protocol. No fixed M10 feature package is declared; future mechanisms should be justified by demonstrated research need rather than feature accumulation.
