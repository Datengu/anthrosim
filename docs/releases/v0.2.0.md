# AnthroSim v0.2.0

## Release scope

AnthroSim v0.2.0 is the audited M8 evidence-grounded spatial experiment baseline.

It builds on the v0.1 deterministic synthetic experiment engine and adds the complete generic path from provenance-tracked external spatial evidence to deterministic, inspectable spatial experiments:

```text
external spatial evidence
    -> pinned/reproducible preprocessing
    -> normalized immutable landscape
    -> explicit model-facing transformations
    -> deterministic spatial ensemble/sweep execution
    -> machine-readable spatial observability
    -> predeclared aggregate interpretation
```

This is a research-software capability release. It does **not** mean AnthroSim is an empirically validated reconstruction of any historical population, settlement, route or archaeological process.

## Major capabilities since v0.1.0

- versioned normalized landscape inputs with provenance and deterministic preprocessing;
- explicit landscape-to-model transformations for movement cost, water access and resource opportunity;
- transformed-spatial execution with separate landscape, mechanism and model-semantics identities;
- evidence catalogues included in immutable experiment identity;
- machine-readable spatial observability and read-only Explorer support;
- M7 ensemble/sweep integration for landscape-bound experiments;
- the first reproducible open-terrain, four-arm, 32-run evidence-grounded M8.6 null-model benchmark;
- cross-platform deterministic golden runs for core, landscape and transformed-spatial execution;
- semantic completed-run bundle validation and deterministic one-file ZIP packing;
- stronger transactional run-directory replacement and crash-recovery tooling;
- exact Git source provenance, collision-resistant dirty-tree identity and exact-binary research-sweep preflight;
- append-only checkpoint resume source lineage;
- correct founder reconstruction for new-directory resumed bundles and Explorer compatibility;
- SHA-256 research-archive integrity manifests;
- a documented future event-storage scaling boundary that preserves the simple small-run representation until measurements justify change.

## Preserved M8.6 scientific baseline

The M8.6 reference remains deliberately modest: **fragile spatial structure**.

Across the predeclared four treatment arms and eight paired seeds, terrain constraints materially perturb some simulated trajectories, but the tested null model does not produce a robust directional effect across seeds in the primary concentration/occupancy metrics.

The v0.2 release candidate is gated against the preserved reference with a provenance-normalized scientific regression check. It requires exact agreement for all 32 authoritative terminal state digests, the predeclared benchmark classification, primary paired-effect summaries, treatment mechanism identities and degeneracy status while permitting expected release/source provenance differences.

This result is about the declared terrain-only model under the tested assumptions. It is not an archaeological validation or historical reconstruction.

## Identity and compatibility

AnthroSim deliberately keeps three identities separate:

- software version: `0.2.0`;
- authoritative model-semantics identity: `anthrosim-model-semantics-v1`;
- exact Git source revision embedded in run provenance.

The v0.2 software release does **not** change `MODEL_SEMANTICS_ID`: the release itself does not introduce a new authoritative scientific mechanism or semantics incompatibility.

### Checkpoint compatibility

The current checkpoint resume policy is intentionally fail-closed and requires the checkpoint `modelVersion` to equal the continuing executable's package version.

Therefore a checkpoint produced by released **v0.1.0 is not resumable by a v0.2.0 executable**, even though both currently carry `anthrosim-model-semantics-v1`.

This restriction is explicit release compatibility behavior, not evidence that the underlying model meaning changed. Exact resume compatibility policy may be revisited separately in a future reviewed change; v0.2 does not weaken it during release.

## Research boundary

Synthetic demographic schedules, resource assumptions and migration weights remain model assumptions rather than calibrated descriptions of a particular society. Strong archaeological or anthropological claims still require question-specific evidence, calibration/validation where appropriate, uncertainty and sensitivity analysis, comparison against independent observations and domain review.

M8 demonstrates that AnthroSim can bind real-world-derived spatial evidence into a deterministic, provenance-preserving experiment pipeline. It does not by itself establish that the resulting agents represent real historical people.

## Release verification

The v0.2.0 release candidate must pass:

- locked workspace tests, formatting and Clippy;
- release build;
- core benchmarks, 1000-run ensemble soak and performance/memory acceptance;
- canonical M7.6 reference experiment;
- M5/M6 bundle integration;
- core cross-platform determinism;
- landscape preprocessing and cross-platform loading determinism;
- transformed-spatial mechanism determinism and M7 sweep integration;
- spatial observability validation;
- new-directory resumed Explorer compatibility;
- deterministic semantic run-bundle packing;
- automatic Git source-provenance tests;
- the canonical M8.6 32-run scientific regression/reproduction gate.

The exact Git revision corresponding to the release must be preserved by the `v0.2.0` tag/release.

## Development boundary

This release freezes the end-of-M8 baseline. It contains no M9 planning, design or implementation. M9 planning may begin only after v0.2.0 is released and the release-readiness governance checks are verified.
