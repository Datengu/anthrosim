# AnthroSim v0.3.0

## Release scope

AnthroSim v0.3.0 is the audited M9 temporary-mobility and controlled-aggregation baseline.

It preserves the v0.2.0 evidence-grounded spatial experiment pipeline and adds a distinct, deterministic temporary-mobility layer so persistent residence, physical presence and permanent M4 migration are no longer conflated:

```text
persistent household residence
    -> optional deterministic temporary departure
    -> outbound transit
    -> focal-region visit
    -> return transit
    -> presence restored at residence
```

This is a research-software capability release. It does **not** establish why a real population gathered, that a real place was continuously or intermittently occupied, or that the simulated mechanisms are empirically validated for prehistory.

## Major capabilities since v0.2.0

- explicit persistent residence versus current physical-presence state;
- identity-bearing focal-region bindings preserved in experiment provenance;
- deterministic temporary-journey scheduling with departure, arrival, visit, return-departure and completion lifecycle events;
- deterministic focal-region travel cost/duration semantics derived from the authoritative world;
- duration-aware resource accounting across residence, visitor and transit person-days;
- explicit home-provisioning proxy for transit, which deliberately has no authoritative per-day world cell;
- checkpoint/resume with active temporary journeys and exact uninterrupted/resumed equivalence;
- machine-readable temporary-mobility observability for residents, visitors, transit, person-days, peaks, journey duration and origin catchment;
- read-only Explorer support for temporary observability alongside residence-based M8 spatial observability;
- controlled M9.7 continuous-residence versus intermittent-aggregation benchmark with a preserved first-observation reference;
- enabled-M9 byte-identical deterministic golden coverage across Linux, Windows and macOS;
- stronger core M9 historical lifecycle replay/invariants;
- full core invariant-validation parity for transformed-spatial runs;
- canonical semantic bundle validation for ordinary, ensemble/retry and transformed-spatial outputs;
- validated evidence parameter paths against the actual versioned serialized experiment schema;
- scheduled/pull-request RustSec dependency advisory scanning;
- fail-closed pathological time and persisted genealogy chronology boundaries.

## Preserved M9.7 scientific capability baseline

The frozen M9.7 benchmark remains **`capability_distinguished`**.

Across paired seeds 9701–9708, intermittent aggregation remains distinguishable from the paired continuous-residence control while total focal-region person-days stay within the predeclared tolerance. The release candidate must preserve the committed scientific reference exactly under the workflow's provenance-normalized comparison.

The v0.3.0 final hardening candidate explicitly reran the benchmark and passed:

- the preserved scientific-reference comparison;
- exact duplicate replay;
- independent temporary-observability reconstruction;
- active-journey annual checkpoint/resume equivalence;
- deliberate reference-tamper rejection.

This result validates the represented capability and observability under the frozen synthetic assumptions only. It is not an archaeological explanation.

## Preserved M8.6 baseline

## Identity and compatibility

AnthroSim deliberately keeps software, model-semantics and source identities separate:

- software version: `0.3.0`;
- authoritative model-semantics identity: `anthrosim-model-semantics-v5`;
- exact Git source revision embedded in run provenance.

M9 changed authoritative model semantics during development, and those reviewed changes are already represented by `anthrosim-model-semantics-v5`. The release-only version/document preparation does **not** change that semantics identity.

Checkpoint resume remains fail-closed on exact package/model-version compatibility. A v0.2.0 checkpoint is therefore not resumable directly by a v0.3.0 executable; this is explicit compatibility policy rather than a migration mechanism.

## Research boundary

Synthetic demographic schedules, resource assumptions, permanent-migration utility and the generic temporary-mobility schedule/travel mechanism remain modelling assumptions unless a particular experiment supplies and validates stronger evidence.

Evidence-grounded input does not automatically make downstream model behaviour empirically valid. Strong archaeological or anthropological claims still require question-specific evidence, uncertainty/sensitivity analysis, competing hypotheses, independent observations and domain review.
