# AnthroSim v0.3.2

## Release scope

AnthroSim v0.3.2 is a **documentation-convergence maintenance release** over v0.3.1.

v0.3.1 correctly preserved the post-v0.3.0 scientific-audit implementation, verification evidence and model semantics. However, when the immutable v0.3.1 tag was created, several living project documents still described the earlier v0.3.0/pre-audit state. That mismatch was a documentation-release sequencing error, not a defect in the preserved v0.3.1 simulation implementation.

v0.3.2 makes that history explicit and provides a release whose package metadata and living scientific/project documentation agree on the same state.

## What changes

This release synchronizes:

- `README.md`;
- `docs/roadmap.md`;
- `docs/scientific-model.md`;
- `docs/research/odd.md`;
- `docs/research/odd-d.md`;
- `docs/research/trace.md`;
- package and citation version metadata.

The synchronized documentation records the first major post-M9 audit backlog as resolved while preserving the requirement for further independent/adversarial audit convergence. It also reflects the v0.3.1 scientific-analysis safeguards around complete configuration exposure, stochastic replicate sufficiency, long-run diagnostics, structural/initialization sensitivity, the no-universal-demographic-baseline result, and fail-closed identifiability/equifinality analysis.

## What does not change

**v0.3.2 does not change model semantics.** In particular, the immutable `v0.3.2` tag preserves `MODEL_SEMANTICS_ID = "anthrosim-model-semantics-v19"`; the maintenance release does not change simulation algorithms, scientific configuration behaviour, frozen M8.6/M9.7 reference results, the #304 demographic-baseline conclusion, or the #217 identifiability/equifinality procedure.

Later post-v0.3.2 scientific repairs have advanced the living development line beyond v19. Those later identities do not retroactively change the semantics recorded by the immutable v0.3.2 tag.

The scientific interpretation boundary is unchanged: AnthroSim remains a research-oriented simulation framework and is **not** an empirically validated reconstruction of a prehistoric population or archaeological site.

## Relationship to v0.3.1

The v0.3.1 release semantics and version identity remain part of the project record. A repository-wide privacy sanitisation on 2026-09-02 subsequently rewrote historical Git object identities, including historical release-tag commit SHAs, without changing the released source semantics. v0.3.2 remains the corrective archival baseline for users who want the post-audit implementation together with documentation that accurately describes it.

This preserves scientific and version provenance while acknowledging the exceptional privacy-driven Git-history rewrite.

## Release verification

The v0.3.2 candidate must pass the ordinary protected-main CI matrix on the exact release candidate. Because the release-tag verifier applies the repository's release-specific gates to named releases from v0.3.0 onward, the exact protected-main v0.3.2 SHA must also have successful M8.6, M9.7 and RustSec dispositions before the immutable `v0.3.2` tag is created.

The release tag must point to the exact protected `main` release commit and must not rewrite any existing tag.
