# AnthroSim v0.3.5 — post-Scientific-Audit-v4 repaired convergence baseline

Release date: 2026-09-07
Software version: `0.3.5`
Model semantics: `anthrosim-model-semantics-v33`
Previous release: `v0.3.4` / `anthrosim-model-semantics-v25`

## Purpose

v0.3.5 freezes the fully repaired and independently re-verified Scientific Audit v4 line as a named patch baseline. It does not add a new roadmap milestone, and the release-preparation change itself does not alter causal simulator behaviour: the authoritative model semantics were already advanced to v33 by the reviewed Audit-v4 repairs.

Scientific Audit v4 independently challenged immutable `v0.3.4` / model-semantics-v25 across Areas A–N. Discovery demonstrated **15 findings: 13 P1 and 2 P2**. Post-discovery remediation repaired every finding and independently re-verified/dispositioned all 15 before closure. The frozen v0.3.4 discovery result therefore remains historically non-clean, while this v0.3.5 baseline represents the repaired living state.

## Scientific semantics progression since v0.3.4

Authoritative Audit-v4 repairs advanced model semantics from v25 through v33 where scientific continuation compatibility changed. The repaired v33 state removes arbitrary identifier/container-order coupling from several stochastic assignments, hardens competing mortality and resource-allocation semantics, and preserves the reviewed current scientific contracts documented by ODD, ODD+D, TRACE and the normative model specification.

The package-version change from 0.3.4 to 0.3.5 is not itself a model-semantics change. Existing historical evidence continues to record the package/model/source identities under which it was actually generated.

## Documentation convergence

After Audit-v4 remediation closed, two repository-wide documentation consistency passes reconciled living status, release/version identities, audit closure, CI/governance wording, citation guidance and historical-versus-current boundaries. Those repairs are included in this baseline. Historical release notes, audit evidence and reviewed experiment records retain the identities they actually evaluated rather than being mechanically rewritten to v0.3.5.

## Benchmark/reference state

- M7.6 resource-variability scientific reference: current model semantics v33. Its reviewed execution retains its actual `0.3.4` package provenance; the 0.3.5 package bump alone does not change the scientific result.
- M8.6 terrain null-model machine reference: current model semantics v33; classification remains `fragile_spatial_structure` under the declared null model.
- M9.7 controlled aggregation machine reference: model semantics v31, intentionally retained because the later v32/v33 pathways are causally inapplicable to that frozen benchmark; classification remains `capability_distinguished`.

These are synthetic capability/regression results, not archaeological validation.

## Interpretation limits

v0.3.5 is a stronger framework-verification/convergence baseline. It does **not** establish empirical calibration for a real population, validate a specific archaeological site, prove model correctness, or remove the need for question-specific evidence roles, uncertainty/sensitivity analysis, identifiability/equifinality assessment, held-out corroboration and domain review.

## Release gate

The `v0.3.5` tag must be created only on the exact current protected-`main` release-candidate SHA after:

1. workspace package version, both workspace entries in `Cargo.lock`, `CITATION.cff`, this release note and living documentation identify v0.3.5 consistently;
2. `MODEL_SEMANTICS_ID` remains the reviewed `anthrosim-model-semantics-v33` identity;
3. every currently required protected-main context is successful on that exact SHA;
4. exact-SHA release-specific M8.6, M9.7 and RustSec gates are successful;
5. there are no open release-preparation PRs or demonstrated release-blocking defects.

Tag creation is deliberately separate from this preparation change. The repository's fail-closed `Preserve named release tag` workflow must perform the final exact-candidate verification before creating the immutable-intent tag.
